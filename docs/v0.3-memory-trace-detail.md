# v0.3 Memory Trace Detail

This document describes the second Zero-CPU v0.3 debugger improvement.

## Goal

Studio can already show raw memory mutations such as:

```text
Memory[180]: 0 -> 30
```

This patch adds a higher-level memory operation snapshot.

The debugger can now explain `LOAD` and `STORE` instructions like this:

```text
STORE [180], R1
address [180] = 180
route = RAM
value R1 = 30
```

And:

```text
LOAD R5, [204]
address [204] = 204
route = RAM
value R5 = 123
destination = R5
```

## Added TraceEvent Data

`TraceEvent` now includes `MemoryTraceDetail`.

The detail contains:

```text
active
operation
address_text
value_text
destination
route
address
value
has_address
has_value
is_read
is_write
note
```

## Supported Instructions

The first version covers:

```text
LOAD
STORE
```

For `LOAD`, the memory detail captures:

```text
- source address operand
- resolved runtime address
- route
- loaded value
- destination register
```

For `STORE`, the memory detail captures:

```text
- destination address operand
- resolved runtime address
- route
- stored value
```

## Route Classification

The route is inferred from the Zero-CPU memory map:

```text
RAM
DebugOutput MMIO
Timer MMIO
MMIO
Outside default RAM
```

This makes direct MMIO writes easier to explain.

Example:

```text
STORE [61440], R6
address [61440] = 61440
route = DebugOutput MMIO
value R6 = 90
note = MMIO write is visible through the device, not normal RAM snapshot
```

## Studio Display

`Execution Detail Probe` now shows memory operation detail inside the Memory
Detail section.

Example:

```text
Memory Detail
  Active = true
  Route = Memory/MMIO
  Operation Detail
    operation = MEMORY_WRITE
    address [180] = 180
    route = RAM
    value R1 = 30
  Memory Mutations = 1
    Memory[180]: 0 -> 30
```

## Why this matters

The old view answered:

```text
Which memory cells changed?
```

The new view also answers:

```text
What address did the instruction target?
What value was read or written?
Was this RAM or MMIO?
Where did a LOAD place the value?
```

## Current Limitations

This is still reconstructed from `TraceEvent` before/after snapshots.

Limitations:

```text
- It does not yet record a first-class bus transaction object.
- MMIO read values are inferred from the destination register after LOAD.
- MMIO writes do not appear in normal RAM memory mutation snapshots.
- PUSH/POP stack value detail is not yet modeled as MemoryTraceDetail.
```

This is acceptable for the second v0.3 patch because it improves LOAD/STORE
explanation without invasive CPU execution refactoring.
