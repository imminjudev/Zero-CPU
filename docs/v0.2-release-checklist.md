## 6. Debugger Showcase Expected Checkpoints

After stepping/running `examples/debugger_showcase.zasm`, check:

```text
Memory[180] = 30
Memory[188] = 60
Memory[196] = 60
Memory[204] = 123
Memory[212] = 90
```

Debug output behavior:

```text
DebugOutputDevice ASCII = ZA
```

Meaning:

```text
Z -> direct MMIO write through STORE [61440], R6
A -> INT 80 syscall 1 debug output
```

## 12. v0.2 Summary

Suggested release summary:

```text
Zero-CPU v0.2 adds a visual Studio debugger on top of the custom CPU platform.
It can assemble .zasm programs into .zbin binaries, load them into virtual
memory, and step through execution while visualizing datapath nodes, pipeline
stages, memory/stack/interrupt behavior, recent trace history, and address-space
regions.
```

## 13. Next Milestone Candidate: v0.3

Recommended v0.3 direction:

```text
Explicit ALU operand/result capture
```

Why:

```text
Studio currently shows register/flag changes after an ALU instruction, but the
TraceEvent model does not yet store explicit ALU input operands and result.

Adding this would allow Studio to show:

ALU_ADD
lhs = 30
rhs = 20
result = 50
destination = R1
```

Other possible v0.3 features:

```text
- interactive memory inspector
- source-line to TraceEvent mapping
- label/symbol viewer
- trace export to JSON/text
- breakpoint UI polish
- BIOS/kernel/user mode separation display
```
