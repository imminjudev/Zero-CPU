# v0.4 Trace Export to JSON

This document describes the first Zero-CPU v0.4 debugger usability feature.

## Goal

Studio can now export recorded `TraceEvent` data to JSON.

This turns the visual debugger trace into data that can be inspected outside the
Studio UI.

## Output Path

The first version exports to:

```text
traces\studio_trace_export.json
```

The `traces` directory is created automatically.

## Studio UI

A new button is added:

```text
[Export Trace]
```

Recommended flow:

```text
Load Source
Assemble
Load BIN
Step or Run
Export Trace
```

## Exported Data

The top-level JSON contains:

```text
schema
schema_version
studio_version
mode
loaded_path
event_count
events
```

Each event contains:

```text
index
pc_before
pc_after
instruction
stage
action
datapath
changed_register_count
changed_flag_count
changed_memory_count
alu_detail
memory_detail
stack_detail
control_flow_detail
compact
full
has_error
error
```

`compact` and `full` preserve the existing TraceEvent textual views, while the
detail fields expose the v0.3 ALU / Memory / Stack / Control Flow summaries.

## Why this matters

v0.3 made the debugger explain each instruction.

v0.4 starts making that debugger output reusable.

The exported trace can be used for:

```text
portfolio evidence
manual inspection
test fixture generation
trace diffing later
external visualization later
debugger regression testing later
```

## Current Limitations

```text
- export path is fixed
- no Save File dialog yet
- no trace filtering before export
- detailed mutations are summarized in this first exporter
- no source-line mapping yet
```

These are acceptable for the first v0.4 patch because the goal is to make trace
data available outside Studio with minimal risk.
