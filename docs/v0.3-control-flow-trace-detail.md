# v0.3 Control Flow Trace Detail

This document describes the fourth Zero-CPU v0.3 debugger improvement.

## Goal

Studio already shows PC movement and stack activity.

This patch adds explicit control-flow interpretation for jumps, branches,
calls, returns, and interrupts.

The debugger can now explain:

```text
CALL double_value
from PC = 608
target = 1016
return address = 632
taken = true
```

And:

```text
RET
from PC = 1040
target = 632
return address = 632
taken = true
```

For conditional branches:

```text
JE label
condition = ZF == 1
taken = false
fallthrough = 680
```

## Added TraceEvent Data

`TraceEvent` now includes `ControlFlowTraceDetail`.

## Supported Instructions

```text
JMP
JE
JNE
JG
JL
CALL
RET
INT
IRET
```

## Condition Handling

Branch conditions are interpreted from the pre-instruction flags.

```text
JE  -> ZF == 1
JNE -> ZF == 0
JG  -> ZF == 0 && SF == 0
JL  -> SF == 1
```

## Studio Display

`Execution Detail Probe` now includes a Control Flow Detail section.

Example:

```text
Control Flow Detail
  Active = true
  Operation = CALL
  Operand = 1016
  From PC = 608
  To PC = 1016
  Taken = true
  Target = 1016
  Return Address = 632
```

## Why this matters

The old view answered:

```text
What is the new PC?
```

The new view also answers:

```text
Why did PC change?
Was the branch taken?
What condition was checked?
Where is the target?
What return address was saved?
Which interrupt vector was used?
```

## Current Limitations

This is reconstructed from `TraceEvent` before/after snapshots.

Limitations:

```text
- Label names are displayed as operands, but label-to-address mapping is not
  stored directly in TraceEvent.
- Conditional branch fallthrough is known when the branch is not taken.
- For label-based branches that are not taken, the target address may be
  unavailable.
- INT/IRET detail is basic and not yet a full interrupt-frame visualizer.
```
